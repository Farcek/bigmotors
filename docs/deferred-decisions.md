# Дараа хэлэлцэх асуудлууд

- Шилжүүлсэн огноо: 2026-09-09
- Төлөв: Хэсэгчлэн хэлэлцэж эхэлсэн; бусад сэдэв хойшлуулсан хэвээр
- Эх бүртгэл: [Tech spec task-ууд](../docs.task.md)

Энэ бүртгэлийг tech spec-ээс бусад асуудлыг дараа хэлэлцэхээр хадгалах зорилгоор үүсгэсэн. 2026-09-09-нд хэрэглэгч features-ийн үндсэн заагийг хэлэлцэж эхэлж, каталог байна, сайтаар худалдахгүй гэдгийг [бүтээгдэхүүний хүрээ](features/scope.md)-д баталсан. Доорх нарийвчилсан саналууд тусад нь батлагдах хүртэл хэвээр үлдэнэ; тэдгээр нь tech spec task-уудыг батлах урьдчилсан шалгуур биш.

## Бизнесийн боломж ба өгөгдөл харуулах дүрэм

2026-09-09-ний тодруулга: CRM нь хойшлуулсан дотоод модуль биш, тусдаа систем. Одоогийн төслийн төвлөрөл нь автомашин, сэлбэг хэрэгсэл, дугуйн каталог болон мэдээллийн удирдлага. CRM холболт, лавлах form болон хүсэлтийн мэдээлэл дамжуулах эсэхийг тусад нь батална; дэлгэрэнгүйг [хүрээ](features/scope.md)-ээс харна.

- Эх task: TASK-01, TASK-05
- Дараа баримтжуулах газар: [Features](features/README.md)
- Автомашины нийтлэх/нуух нөхцөл [талбарын баримтад](features/vehicle-fields.md), public талбар, хайлт, шүүлт, эрэмбэ [каталогийн баримтад](features/vehicle-catalog.md) батлагдсан. Арлын дугаар болон дотоод тэмдэглэл зөвхөн admin-д байна.
- Бодит endpoint, request/response бүтэц, текст хайлтын нарийвчилсан тохирол, pagination-ийн тоон хязгаар, admin-ийн засварлах эрх болон сэлбэг/дугуйн онцлог public/filter талбарууд нээлттэй хэвээр. Төрлүүдийн [нийтлэг дүрэм](features/product-common-rules.md) батлагдсан.
- Автомашины үндсэн жагсаалт зөвхөн `published + available`; зарагдсан, нийтлэгдсэн дэлгэрэнгүй хуудсыг тэмдэглэгээтэй хадгалах батлагдсан дүрэм үйлчилнэ.

## Admin хэрэглэгчийн урсгал ба эрх

- Эх task: TASK-03
- Дараа баримтжуулах газар: [Features](features/README.md)
- 2026-09-10: Chip CRM-ийн Userly admin login/user management/ACL аргачлалыг [ADR 0019](adr/0019-use-userly-admin-authentication-and-acl.md), [admin feature](features/admin-authentication-access.md)-д баталсан. Account/invitation/password/reset, membership, role/permission/access lifecycle нь Userly-ийн үүрэг; local user-management screen хийхгүй.
- Memory-only token, 900 секундийн Userly TTL, refresh token ашиглахгүй байх, re-login/logout болон ACL snapshot cache/recovery зарчим батлагдсан. TASK-03-т үлдсэн SDK/API/config болон multi-instance техникийн нарийвчлалыг шийднэ.
- Каталогийн action permission/scope matrix, local profile metadata/schema болон Userly дээрх бодит role composition нээлттэй. Өмнөх `admin`/`editor` role нэрийг application дээр hardcode хийх санал үйлчлэхгүй.
- MFA/reset зэрэг provider policy-ийн байгууллагын бодит тохиргоог Userly талд шийднэ; BigMotors өөрийн MFA/password урсгал давхар хэрэгжүүлэхгүй.

## Schema-ийн дэлгэрэнгүй загвар

- Эх task: TASK-04
- Дараа баримтжуулах газар: [DB](db/README.md)
- ERD, хүснэгт, талбар, холбоос, unique constraint, индекс болон бизнес өгөгдлийн дүрэм.
- Дараагийн хэлэлцүүлгийн сэдэв: Автомашин, марк/модель, зураг, үйлчилгээ, компанийн агуулга, account/session.
- Автомашины борлуулалтын болон нийтлэлийн төлөвийн ялгаа, төлөв шилжилт ба архивлах дүрэм, зөвхөн `MNT` валют болон тоон талбарын нэгж, бүхэл тоон хязгаар [талбарын баримтад](features/vehicle-fields.md) батлагдсан. Эдгээр нь DB баганын төрөл болон constraint-ийн хэрэгжүүлэлтийг баталсан гэсэн үг биш.
- Үлдсэн санал: UTC цаг, UUID танигч, устгах бодлого болон сэлбэг/дугуйн үнийн нэгжийн нарийвчлал. Үнэ/валютын нийтлэг хязгаар, харуулах дүрэм гурван төрөлд ижил батлагдсан.
- Schema, CRUD, migration болон seed-ийг `packages/db` хариуцах батлагдсан үүрэг хэвээр байна.

## Зураг ба upload-ийн бүтээгдэхүүний дүрэм

- Эх task: TASK-06
- Дараа баримтжуулах газар: [Features](features/README.md), [UI / UX](ui/README.md)
- Автомашины зургийн тоонд дээд хязгааргүй, зураг бүр сонголттой гарчиг/тайлбартай, форматын тогтсон хязгаарлалтгүй, upload хийсэн эх зураг өөрчлөлтгүй хадгалагдах шаардлага [талбарын баримтад](features/vehicle-fields.md) 2026-09-10-нд батлагдсан. Үндсэн зураг болон дарааллын өмнөх дүрэм хэвээр.
- Өмнөх автомашин бүр 30 зураг, зөвхөн JPEG/PNG/WebP гэсэн саналууд үйлчлэхгүй. Зураг бүр 10 MB байх санал батлагдаагүй хэвээр; файл/пикселийн техникийн хязгаар болон upload урсгалыг тусад нь шийднэ.
- Браузер зураг харуулж чадах эсэхийг шалгахгүй; харуулж чадахгүй байсан ч upload, хадгалах, нийтлэхийг хориглохгүй. Эх зургийг энгийн байдлаар ашиглаж, тусгай preview эсвэл хөрвүүлэлт шаардахгүй гэж баталсан; энэ асуудал нээлттэй биш.
- Зургийн гарчиг 255, тайлбар 512 тэмдэгтийн дээд урттай гэж баталсан. Зургийн тоо, формат, эх файл, браузерын дэмжлэг шалгахгүй байх дүрмийг сэлбэг/дугуйд мөн [ижил хэрэглэнэ](features/product-common-rules.md). Public metadata харагдах байдал, устгах/хадгалах хугацаа болон сэргээх шаардлага нээлттэй.
- Storage API/SDK, processing сан болон upload transport сонголт TASK-06-д үлдэнэ.

## UI дизайн ба дэлгэцийн урсгал

- Эх task: TASK-07
- Дараа баримтжуулах газар: [UI / UX](ui/README.md)
- Брэндийн theme, өнгө, үсгийн хэв, layout, хуудасны загвар, responsive зохиомж.
- Loading/empty/error төлөвийн харагдах байдал, текст, навигаци болон filter-ийн хэрэглэгчийн урсгал.
- Өмнөх санал: Filter, эрэмбэ, pagination-ийг URL-д хадгалах; бодит route болон дэлгэцийн урсгалтай хамт хэлэлцэнэ.
- Styling арга, router, form болон server-state сангийн сонголт TASK-07-д үлдэнэ.

## SEO агуулга ба хуудасны бодлого

- Эх task: TASK-08
- Дараа баримтжуулах газар: [Features](features/README.md)
- Автомашины URL/slug, metadata агуулга, canonical, filter URL-ийн индексжүүлэлт болон sitemap-д орох хуудсууд.
- Борлуулсан/устгасан автомашины хуудасны үйлдэл, redirect болон мэдээлэл шинэчлэгдэх зөвшөөрөгдөх хоцролт.
- 2026-09-10: Зарагдсан машиныг үндсэн жагсаалтаас хасаж, нийтлэгдсэн дэлгэрэнгүй хуудсыг "Зарагдсан" тэмдэглэгээтэй хадгалах, нийтлэгдээгүй машины мэдээллийг шууд холбоосоор ч нийтэд харуулахгүй байх бодлого [автомашины баримтад](features/vehicle-fields.md) батлагдсан.
- Үлдсэн санал: Устгасан хуудасны 404/410 хариу; тогтвортой мэдээллийг cache-лах, үнэ/төлөвийг хүсэлт бүрд шинэ унших. HTTP хариу болон cache-ийн нарийвчилсан бодлого батлагдаагүй.
- Rendering, cache/revalidation болон metadata үүсгэх техник TASK-08-д үлдэнэ.

## PWA-ийн хэрэглэгчийн боломжууд

- Эх task: TASK-09
- Дараа баримтжуулах газар: [PWA шаардлага](features/pwa.md), [UI / UX](ui/README.md)
- Суулгах UI/урсгал, offline үед харуулах мэдээлэл, push, background sync, admin PWA болон эхний хувилбарын хүрээ.
- Дэмжих төхөөрөмж/browser-ийн бүтээгдэхүүний шаардлага болон update мэдэгдлийн харагдах байдал.
- Өмнөх санал: Энгийн offline хуудас, static asset cache; үнэ/нөөцтэй API response-ийг offline хадгалахгүй, push/background sync/admin PWA-г эхний хувилбарт оруулахгүй. Энэ санал бүхэлдээ батлагдаагүй.
- Public website PWA дэмжих батлагдсан шаардлага хэвээр. Интеграц болон service worker технологийг TASK-09-д шийднэ.

## Ашиглалтын бизнес нөхцөл ба хариуцлага

- Эх task: TASK-12
- Дараа баримтжуулах газар: [Operations](operations/README.md)
- Hosting provider-ийн эцсийн худалдан авалт, бүс, сарын төсөв, домэйны яг нэр, release болон incident-ийн хүний хариуцагч.
- Backup/log хадгалах хугацаа, backup давтамж, зөвшөөрөх өгөгдлийн алдагдал (RPO), сэргээх хугацаа (RTO), SLA болон мэдэгдэл хүлээн авах суваг.
- Өмнөх санал: Тусдаа staging, өдөр тутмын backup, сэргээх туршилт, admin өөрчлөлтийн audit log. Орчны тоо, давтамж болон бизнес audit event-үүдийг дараа батална.
- Deployment/proxy, secrets, migration job, backup/restore болон monitoring-ийн техникийн механизм TASK-12-д үлдэнэ.
