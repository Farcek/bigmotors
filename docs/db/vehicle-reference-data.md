# Автомашины лавлах ба тогтмол сонголтууд

- Огноо: 2026-09-10
- Төлөв: Баталсан
- Үндэслэл: Хэрэглэгч автомашины 7 DB лавлах, лавлах хөтлөх зарчим болон 10 enum/const бүлгийн утга, утгын кодыг баталсан
- Холбоотой баримт: [Автомашины талбарууд](../features/vehicle-fields.md), [ADR 0016](../adr/0016-separate-vehicle-lookups-and-constants.md)

## Хүрээ

Автомашины талбаруудын сонголтыг DB-д хадгалах лавлах болон кодод хөтлөх тогтмол бүлэгт ялгана. Нийт **7 DB лавлах нь 8 талбарт**, **10 enum/const бүлэг нь 10 талбарт** ашиглагдана. Энэ нь 17 DB хүснэгт үүсгэнэ гэсэн үг биш.

Энэ баримт логик ангилал болон автомашины enum/const сонголтын утга, утгын кодыг хариуцна. Дараагийн баталгаагаар хүснэгт, нийтлэг багана, төрөл, холбоос болон нэрийн давхардлын дүрмийг [лавлахын schema баримтад](reference-tables.md) баталсан. TypeScript бүлгийн identifier, enum/const-ийн DB хадгалалтын төрөл, seed болон migration-ийн хэрэгжүүлэлт тусдаа үлдэнэ. Сэлбэг/дугуйн enum/const утга болон тэдгээрийг автомашинтай нэгтгэх эсэхийг тусад нь шийднэ.

## DB лавлах

| ID | Лавлах | Ашиглах талбар | Хамаарал, сонголт |
| --- | --- | --- | --- |
| L01 | Марк | V02 Үйлдвэрлэгч / марк | Машины үйлдвэрлэгчээс нэгийг сонгоно |
| L02 | Загвар | V03 Загвар | Маркт харьяалагдана; сонгосон маркын загвараас нэгийг сонгоно |
| L03 | Хувилбар / комплектаци | V04 Хувилбар / комплектаци | Загварт харьяалагдана; сонгосон загварын хувилбараас нэгийг сонгоно |
| L04 | Кузовын төрөл | V08 Кузовын төрөл | SUV, sedan, pickup зэрэг; жишээ нь бүрэн seed жагсаалт биш |
| L05 | Өнгө | V14 Гадна өнгө, V15 Салоны өнгө | Нэг лавлахыг хоёр талбарт ашиглаж, тус бүрд нэгийг сонгоно |
| L06 | Салбар / байршил | V19 Байршил / салбар | Компанийн бодит салбараас нэгийг сонгоно |
| L07 | Тоноглол, нэмэлт боломж | V29 Тоноглол, нэмэлт боломжууд | Нэг машинд олон утга сонгож болно |

### Хөтлөх дүрэм

- Admin-аас лавлах нэмэх, нэр засах, идэвхгүй болгох боломжтой байна.
- Ашиглагдаж байгаа лавлахыг шууд устгахгүй.
- Марк -> загвар -> хувилбар гэсэн хамаарлаар сонгоно. Хоорондоо зөрсөн хослол сонгохгүй.
- Идэвхгүй болгосон лавлахыг шинэ сонголтод санал болгохгүй; өмнө сонгосон машины холбоос болон мэдээллийг алдахгүй.
- Идэвхгүй болгох нь тухайн лавлахыг ашигласан бүх машиныг устгах эсвэл автоматаар нуух үйлдэл биш.
- Нэмэх/засах/идэвхгүй болгох эрхтэй admin role-ийг нарийвчлан тогтоох ажил тусдаа үлдэнэ.

Кузовын төрөл нь тусдаа ерөнхий маркетингийн category гэсэн үг биш. Luxury зэрэг сегмент, шинэ ирэлт зэрэг төлөвийг кузовын төрлийн лавлахтай нэгтгэхгүй.

### Идэвхгүй лавлахтай автомашин

2026-09-10: Идэвхгүй болгох нь шинэ сонголтыг хаана, өмнөх машины бүртгэлийг хүчингүй болгохгүй гэсэн дүрмийг баталсан.

| Нөхцөл | Батлагдсан дүрэм |
| --- | --- |
| Шинэ машин бүртгэх | Зөвхөн идэвхтэй лавлахаас сонгоно |
| Өмнө сонгосон лавлах идэвхгүй болсон | Сонголт, холбоосыг хэвээр хадгална |
| Машины бусад мэдээллийг засах | Идэвхгүй лавлахыг заавал солихыг шаардахгүй |
| Ноорог эсвэл нуусан машиныг нийтлэх | Өмнө сонгосон идэвхгүй лавлахтай байсан ч бусад нийтлэх шаардлага хангагдсан бол зөвшөөрнө |
| Лавлахын сонголтыг өөрчлөх | Шинээр зөвхөн идэвхтэй утга сонгоно |
| Public сайт дээр харуулах | Лавлахын нэрийг хэвийн харуулна; "идэвхгүй" тэмдэглэгээг зөвхөн admin-д үзүүлнэ |

Марк -> загвар -> комплектацийн хамаарлыг үргэлж шалгана. Марк эсвэл загварыг солиход тохирохгүй доод сонголтуудыг цэвэрлэж, дахин сонгуулна; сонголттой комплектацийг заавал бөглүүлэхгүй, харин загварын нийтлэх шаардлага хэвээр. Өмнөх идэвхгүй сонголтыг хадгалах нь хоорондоо зөрсөн марк/загвар/комплектаци зөвшөөрөх үндэслэл биш.

Идэвхгүй лавлахтай бүх машиныг автоматаар нуухгүй, бөөнөөр солихыг шаардахгүй. Алдаатай мэдээллийг нийтэд харуулахгүй болгох бол тухайн машиныг тусад нь `hidden` болгоно. Дараагийн баталгаагаар энэ зарчмыг сэлбэг/дугуйд мөн [ижил хэрэглэнэ](../features/product-common-rules.md).

### Хөтлөх дүрэм

- Эдгээр 10 бүлгийг admin-аас дурын утга нэмдэг DB лавлах биш, кодын enum/const байдлаар удирдана.
- Website болон admin-д дундын enum/const-ыг `packages/core`-д хөтлөх өмнө баталсан үүргийг баримтална. Энд код үүсгээгүй.
- TypeScript `enum` эсвэл `as const` ашиглах яг хэлбэрийг энэ шийдвэрээр тогтоогоогүй. PostgreSQL enum ашиглахыг мөн автоматаар батлаагүй.
- [Талбарын баримтад](../features/vehicle-fields.md) баталсан default, нөхцөлтэй заавал шаардлага болон хоосон утгын утгыг хадгална. Шинэ/хуучин, ирэлтийн, борлуулалтын, нийтлэлийн төлөвүүдийг нэгтгэхгүй.
- Boolean шинжтэй зээлээр авах боломж болон онцлох эсэх нь энэ 10 бүлгийн тоонд ороогүй. Тэдгээрийн батлагдсан дүрэм хэвээр.

### Утга ба төлөвийн дүрэм

- Эхний хувилбарт автомашины валют зөвхөн `MNT`; нэмэлт валют болон ханш хөрвүүлэх боломж оруулахгүй. Үнэ оруулсан үед валют заавал байх өмнөх шаардлага хэвээр.
- Борлуулалтын төлөвт одоогоор `reserved` нэмэхгүй; шаардлага гарвал тусад нь батална.
- Ерөнхий `unknown`, `other` утга нэмэхгүй. Мэдээлэл тодорхойгүй бол ноорогт хоосон үлдээнэ; заавал талбар дутуу бол нийтлэхгүй.
- Түлш, хурдны хайрцаг, борлуулалтын болон ирэлтийн төлөвийг автоматаар тааж сонгохгүй. Нийтлэлийн анхны төлөв `draft`, онцлох эсэхийн анхны утга `false` хэвээр.
- Борлуулалтын төлөв нь борлуулах боломжийг, ирэлтийн төлөв нь ирэлтийн явцыг, нийтлэлийн төлөв нь сайт дээрх харагдах байдлыг тус тус илэрхийлнэ. Нэгийг өөрчлөхөд нөгөөг автоматаар өөрчлөх дүрэм энд батлаагүй.
- `available + in_transit + published` нь замд яваа, борлуулах боломжтой машиныг нийтэлсэн жишээ. `sold + in_stock + published` нь үндсэн жагсаалтаас хасагдсан ч дэлгэрэнгүй хуудас нь "Зарагдсан" тэмдэглэгээтэй нээлттэй машины жишээ.
- 2026-09-10-нд төлөв шилжилт болон зарагдсан машины харагдах байдлыг баталсан. Үндсэн дүрмийг [автомашины талбарын баримтад](../features/vehicle-fields.md) хөтөлнө. Одоогийн нийтлэх болон нийтлэгдсэн мэдээлэл засах шалгалт хэвээр; admin role бүрийн нарийвчилсан эрх нээлттэй.

## Дараа шийдэх зүйлс

- 7 лавлахын хүснэгт, нийтлэг багана, холбоос болон нэрийн давхардлын дүрэм [батлагдсан](reference-tables.md). Нэрийн normalization болон constraint/index-ийн яг хэрэгжүүлэлт нээлттэй.
- Марк/загвар/хувилбарын бодит өгөгдлийн эх үүсвэр, seed жагсаалт болон хувилбарын он/үеийн нарийвчлал.
- Enum/const бүлгийн TypeScript identifier, `enum` эсвэл `as const` хэлбэр болон DB хадгалалтын төрөл. Дээрх утгын код, нэр, жагсаалт батлагдсан.
- Лавлах удирдах болон машины төлөв шилжүүлэх үйлдэл бүрийн permission matrix. Идэвхгүй лавлахтай машиныг засах, дахин нийтлэх дүрэм дээр батлагдсан.
- Сэлбэгийн марк, загвар, салбарыг автомашинтай хамт ашиглах хүрээ [ADR 0017](../adr/0017-use-part-reference-data.md), дугуйн салбарыг мөн хамт ашиглах хүрээ [ADR 0018](../adr/0018-use-tire-reference-data.md)-аар батлагдсан. Бусад нээлттэй асуудал болон enum/const-ийн дундын хэрэглээг тусад нь шийднэ.

## Баталгаажуулалтын зааг

2026-09-10: Лавлахын ангилал, хөтлөх зарчмыг баталсны дараа хэрэглэгч автомашины 10 enum/const бүлгийн 33 утга, утгын код, нэр болон дээрх утга ба төлөвийн дүрмийг баталсан.

2026-09-10: Хэрэглэгч идэвхгүй лавлахын өмнөх сонголтыг хадгалж засах/дахин нийтлэх, шинэ сонголтод зөвхөн идэвхтэй утга ашиглах, хамаарлыг шалгах болон public/admin тэмдэглэгээний ялгааг баталсан.

DB лавлахын бодит өгөгдлийн бүрэн жагсаалт, DB schema, migration, seed, admin UI эсвэл кодын хэрэгжүүлэлт дууссан гэсэн үг биш. Автомашины бөглөх шаардлага болон tech spec task-уудын төлөв өөрчлөгдөөгүй. Сэлбэг/дугуйд дараа нь баталсан [нийтлэг дүрмийн хүрээ](../features/product-common-rules.md) үйлчилнэ; автомашины онцлог enum/default/validation-г шууд хуулбарлахгүй.
