# 0018: Дугуйн үндсэн лавлах ба enum/const ангиллыг тогтоох

- Огноо: 2026-09-10
- Төлөв: Баталсан
- Үндэслэл: Хэрэглэгч дугуйн лавлахын саналыг баталсан
- Холбоотой баримт: [Дугуйн лавлахын бүртгэл](../db/tire-reference-data.md), [Дугуйн талбарууд](../features/tire-fields.md), [ADR 0016](0016-separate-vehicle-lookups-and-constants.md), [ADR 0017](0017-use-part-reference-data.md)

## Нөхцөл байдал

Дугуйн брэнд, загвар, салбарын лавлахыг техникийн хэмжээ, тогтмол сонголт болон үйлдвэрлэгчийн кодоос ялгах шаардлагатай. Автомашин, сэлбэгийн салбарын лавлахыг давхардуулахгүй.

## Харьцуулсан хувилбарууд

- Бүх талбарыг DB лавлах болгох: хэмжээ болон кодын өгөгдлийг хөтлөх нэмэлт ажил үүсгэнэ.
- Бүх мэдээллийг текстээр хөтлөх: брэнд/загварын хамаарал, салбарын дундын хэрэглээ алдагдана.
- Үндсэн 3 лавлахыг тоон утга, код, boolean болон 11 enum/const бүлгээс ялгах: сонгосон хувилбар.

## Шийдвэр

Дугуйн брэнд, тухайн брэндийн загвар гэсэн 2 шинэ лавлах болон автомашин/сэлбэгтэй дундын салбарын лавлах ашиглана. Нэг загвар олон хэмжээтэй бүтээгдэхүүнд хэрэглэгдэнэ.

Нөхцөл, хийц, улирал, тээврийн хэрэгслийн зориулалт, замын зориулалт/хээний төрөл, хадаасны төлөв, валют, үнэ харуулах хэлбэр, үнийн нэгж, бэлэн байдлын төлөв, нийтлэлийн төлөв гэсэн 11 бүлгийг enum/const болгоно.

Өргөн, харьцаа, обудны диаметр нь тоо; SKU болон үйлдвэрлэгчийн код нь кодын талбар; run-flat болон онцлох эсэх нь boolean шинжтэй байна. Ачааллын/хурдны индекс болон нэмэлт тэмдэглэгээний аргыг дараа шийднэ.

## Үр дагавар

- Салбар нь автомашин, сэлбэг, дугуй гурвууланд дундын болно; тусдаа хуулбар үүсгэхгүй.
- Дугуйн брэнд/загварыг автомашины марк/загвартай утгын хувьд нэгтгэхгүй.
- Бүрэн сонголт, DB хадгалалт, лавлахын бодит өгөгдөл болон хэрэгжүүлэлт тусдаа үлдэнэ. Өмнөх шийдвэр, бусад талбар болон tech spec task-ийн төлөв өөрчлөгдөөгүй.
