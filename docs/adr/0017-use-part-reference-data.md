# 0017: Сэлбэгийн үндсэн лавлах ба enum/const ангиллыг тогтоох

- Огноо: 2026-09-10
- Төлөв: Баталсан
- Үндэслэл: Хэрэглэгч сэлбэгийн лавлахын саналыг баталсан
- Холбоотой баримт: [Сэлбэгийн лавлахын бүртгэл](../db/part-reference-data.md), [Сэлбэгийн талбарууд](../features/part-fields.md), [ADR 0016](0016-separate-vehicle-lookups-and-constants.md)

## Нөхцөл байдал

Сэлбэгийн өөрийн ангилал, брэндийг автомашинд тохирох марк/загвараас ялгах хэрэгтэй. Автомашины лавлахууд батлагдсан тул ижил өгөгдлийн хуулбар үүсгэхгүйгээр ашиглах хүрээг тогтооно.

## Харьцуулсан хувилбарууд

- Бүх лавлахыг сэлбэгт тусад нь хөтлөх: марк, загвар, салбар давхардаж зөрөх эрсдэлтэй.
- Бүх брэнд, ангиллыг шууд нэгтгэх: сэлбэгийн үйлдвэрлэгч болон тохирох машины маркын ялгааг бүдгэрүүлнэ.
- Сэлбэгт 2 шинэ, автомашинтай 3 дундын лавлах ашиглах: энэ хувилбарыг сонгосон.

## Шийдвэр

Сэлбэгийн шаталсан ангилал, сэлбэгийн брэнд гэсэн 2 шинэ лавлах; автомашины марк, загвар, салбар гэсэн 3 дундын лавлах ашиглана. Нийт 5 үндсэн лавлах байна.

Нөхцөл, суурилуулах байрлал, валют, үнэ харуулах хэлбэр, үнийн нэгж, бэлэн байдлын төлөв, нийтлэлийн төлөв гэсэн 7 бүлгийг enum/const байдлаар хөтөлнө.

Сэлбэгийн цуврал, автомашины үе/кузовын код, хөдөлгүүрийн код гэсэн нэмэлт 3 лавлахыг хэрэгцээгээр дараа шийднэ. SKU, part number, OEM дугаарууд нь эхний хувилбарт сонгодог лавлах биш, бүтээгдэхүүний код/дугаар байна.

## Үр дагавар

- Дундын лавлахыг давхар хөтлөхгүй; марк/загварын хамаарлыг хадгална.
- Бүртгэлийн дэлгэрэнгүй болон үлдсэн шийдвэрийг [үндсэн баримтад](../db/part-reference-data.md) хөтөлнө.
- Энэ нь enum-ийн бүх утга, сэлбэгийн бүх талбар, DB schema эсвэл кодын хэрэгжүүлэлтийг батлахгүй. ADR 0016-ийн автомашины ангилал болон tech spec task-ийн төлөв хэвээр.
