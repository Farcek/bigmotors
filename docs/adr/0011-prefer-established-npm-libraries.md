# 0011: Нийтлэг хэрэгцээнд тогтсон npm санг түлхүү ашиглах

- Огноо: 2026-09-08
- Төлөв: Баталсан
- Үндэслэл: Хэрэглэгчийн код хөгжүүлэлтийн зарчим
- Холбоотой баримт: [Agent-ийн заавар](../../AGENTS.md), [Үндсэн сангууд](0004-use-napp-libraries.md), [TypeScript](0006-use-typescript-for-all-code.md)

## Нөхцөл байдал

Validation, helper function болон бусад нийтлэг үйлдлийг хэрэгжүүлэхдээ бэлэн сан ашиглах эсэхийг шийдэх нэгдсэн зарчим шаардлагатай.

## Харьцуулсан хувилбарууд

- Нийтлэг үйлдэлд тогтсон npm сан ашиглах: бэлэн хэрэгжүүлэлтийг ашиглаж, өөрсдөө хөтлөх кодыг багасгана; dependency-ийн нийцэл, шинэчлэлтийг хариуцна.
- Нийтлэг үйлдлийг өөрсдөө бичих: хэрэгжүүлэлт, онцгой тохиолдол болон тестийг төсөл өөрөө хариуцна.

## Шийдвэр

- Бүх monorepo package-д validation, parsing, formatting, огноо болон өгөгдөл боловсруулах helper зэрэг нийтлэг хэрэгцээнд стандарт, өргөн хэрэглэгддэг, хөтлөгдөж буй npm санг аль болох түлхүү ашиглана.
- Энд "стандарт npm сан" гэдэг нь экосистемд тогтсон санг хэлнэ; npm-д нийтлэгдсэн байх нь дангаараа чанарын шалгуур биш.
- Эхлээд төслийн батлагдсан dependency болон одоо ашиглаж буй сан тухайн хэрэгцээг хангах эсэхийг шалгана. Ижил зориулалттай санг давхар нэмэхээс зайлсхийнэ.
- Шинэ сан сонгохдоо шаардлагад нийцэх байдал, TypeScript дэмжлэг, Node.js болон browser орчны нийцэл, хөтлөлт, лиценз, dependency болон bundle-ийн хэмжээг харгалзана.
- JavaScript/Node.js-ийн built-in API хэрэгцээг бүрэн хангаж байвал түүнийг ашиглаж болно. Жижиг үйлдэл бүрд шинэ dependency нэмэх шаардлагагүй.
- Компанийн бизнес дүрэм, төслийн онцлог логик, сангуудын холболт болон бэлэн сангаар хангах боломжгүй helper-ийг TypeScript дээр бичнэ. Шаардлагатай custom helper нь `core`-д байх үүргийг энэ зарчим өөрчлөхгүй.
- Library API-г шууд ашиглах нь ойлгомжтой байвал нэмэлт wrapper үүсгэхгүй. Wrapper нь төслийн дүрэм эсвэл давтагдсан холболтыг нэгтгэх бодит хэрэгцээтэй байна.

## Үр дагавар

- Нийтлэг алгоритм, validation engine болон utility-г дахин хэрэгжүүлэхээс өмнө бэлэн шийдлийг шалгана.
- Тестийг сангийн дотоод хэрэгжүүлэлтийг давтахад бус, төслийн validation дүрэм, бизнес логик болон сангийн холболтын зөв ажиллагаанд чиглүүлнэ.
- Шинэ dependency-ийн зориулалтыг өөрчлөлтийн тайлбарт тэмдэглэнэ. Архитектур эсвэл нийтлэг contract-д нөлөөлөх сонголтыг ADR-д бүртгэнэ.
- Энэ шийдвэрээр тодорхой validation эсвэл helper сан шинээр сонгоогүй, суулгаагүй. Сангийн нэр, хувилбарыг бодит шаардлагад тулгуурлан тогтооно.
