# Автомашины лавлахын гурван багана

- Төлөв: Хэрэгжүүлсэн, 2026-09-12.
- URL: `/references/vehicle-hierarchy`.
- Navigation: Лавлах → Марк / Загвар / Хувилбар.
- Хамаарал: [Лавлахын CRUD](admin-reference-crud.md), [Admin UI kit](../ui/admin-ui-kit.md).

## Хэрэглэгчийн урсгал

Нэг цагаан ажлын хэсэг дотор зүүнээс баруун тийш **Марк → Загвар → Хувилбар** гэсэн гурван багана байна.

- Марк сонгоход зөвхөн түүний загварууд ачаална; өмнөх загварын сонголт болон хувилбарын жагсаалт цэвэрлэгдэнэ.
- Загвар сонгоход зөвхөн түүний хувилбарууд ачаална.
- Марк/загвар сонгоогүй үед харьяалах багана сонголт хүлээсэн төлөвтэй. Харьяалах сонголтгүйгээр дэд бүртгэл нэмэхгүй.
- Багана бүр нэмэх, шинэчлэх товчтой. Шинэчлэх нь тухайн баганын API уншилтыг дахин хийнэ.
- Мөр бүр гурван цэгтэй үйлдлийн цэстэй. Цэснээс засах эсвэл баталгаажуулалттай устгах үйлдлийг сонгоно. Цэс нээхэд тухайн мөрийг автоматаар сонгохгүй. Ашиглагдаж буй лавлахын устгах хориг хэвээр.
- Шинээр марк/загвар нэмсний дараа түүнийг сонгож, дараагийн баганыг ачаална.
- Марк/загварын сонголт `brandId`, `modelId` URL query-д хадгалагдана. Refresh, Back/Forward үед сонголтыг сэргээнэ. Сонгосон маркт хамаарахгүй загвараар хувилбар ачаалахгүй.

## Нэмэх ба засах form

- Марк нэмэхэд харьяалах талбар байхгүй.
- Загвар нэмэхэд сонгосон марк автоматаар бөглөгдөнө.
- Хувилбар нэмэхэд сонгосон марк болон загвар хоёул харагдана. API body-д зөвхөн `modelId` илгээнэ; `brandId` нь загвараар тодорхойлогдоно.
- Автоматаар бөглөсөн харьяалал form дотор өөрчлөгдөхгүй. Өөр харьяалалд нэмэх бол form-оо хааж тухайн баганаас сонгоно.
- Form нээсэн үеийн харьяаллыг хадгална. Алдаа болон reset үед нэр/тайлбарын form төлөвтэй хамт харьяалал өөр газар шилжихгүй.
- Засахад харьяалах ID-ууд PATCH body-д орохгүй. Mantine `useForm`, DTI validation болон нийтлэг лавлахын form дүрмийг ашиглана.
- Идэвхгүй марк доор загвар нэмэхгүй. Хувилбар нэмэхэд марк, загвар хоёул идэвхтэй байх ёстой. Өмнөх дэд бүртгэлийг засах боломж хэвээр.

## Ачаалал ба харагдац

- Багана бүр тусдаа loading, error/retry, empty төлөв болон босоо scroll-той.
- API нь хуудсалсан тул тухайн харьяаллын бүх мөрийг 100-аар дараалан уншина. Эхний 100 дээр таслахгүй; бүрэн уншсан тоог баганын доор харуулна.
- Parent өөрчлөгдвөл хуучин хүсэлтийг цуцална; оройтож ирсэн хариу шинэ сонголтын мөрүүдийг дарж солихгүй.
- Mutation амжилттай бол холбогдох баганыг дахин уншина. Нэмэлт cache, optimistic update, automatic retry байхгүй.
- Desktop дээр гурван багана зэрэг харагдана. Mantine-ийн `sm` breakpoint (одоогоор 768px)-ээс нарийн дэлгэцэд нэг багана болж, Марк → Загвар → Хувилбар дарааллаар доош байрлана; 768px-ээс эхлээд гурван багана байна. Хэсэг бүр өөрийн босоо scroll-той; гар утсанд хөндлөн гүйлгэх шаардлагагүй. Нарийн desktop/tablet дээр гурван багана зөвхөн ажлын хэсэг дотроо хөндлөн гүйнэ. Үйлдлийн цэс scroll хэсгийн гадна portal-д нээгдэж, таслагдахгүй.
- Mobile дээр хэсэг бүрийн гарчиг саарал дэвсгэртэй, 3px дээд заагтай, томруулсан гарчигтай байна. Хэсгүүдийн хооронд 24px зай авч, мөрийн нимгэн тусгаарлагчаас ялгана. Давхар card үүсгэхгүй; desktop хэвээр.
- Hierarchy-ийн тусгай CSS class/media query ашиглахгүй. Байрлал, scroll, зааг, мөрийн сонголтыг Mantine `SimpleGrid`, `Stack`, `Flex`, `ScrollArea`, `Divider`, `NavLink` болон responsive props-оор шийднэ. Нийтлэг `PageBody`-ийн style энэ өөрчлөлтөд хамаарахгүй.
- Урт мөрийн нэрийг Mantine `Text truncate`-аар багтааж, бүтэн нэрийг `title` болон accessible name-д хадгална. Устгах цонхонд нэрийг бүтнээр нь харуулахын тулд `overflowWrap: "anywhere"` гэсэн ганц inline style үлдэнэ: Mantine `Text` нь үүнийг тохируулах бэлэн prop-гүй.

## Өөрчлөлтийн зааг

Лавлахын нүүрний гурван тусдаа холбоосыг нэгтгэсэн. Өмнөх `/references/vehicle-brands`, `/references/vehicle-models`, `/references/vehicle-variants` URL-уудыг шууд хандалтын нийцэлд хэвээр хадгалсан. Бусад лавлах өөрчлөгдөөгүй.

API contract, service, DB schema, migration болон Userly/ACL бодлогыг өөрчлөөгүй. Тусдаа шинэ tree endpoint нэмээгүй.
