Create/update/get/list contract болон DB service-д ижил талбартай; input validation-ийн дүрэм [автомашины талбар](vehicle-fields.md)-т байна. Migration: `0007_vehicle_youtube_url.sql`.

| URL | Зориулалт |
| --- | --- |
| `/vehicles` | Хайлт, шүүлт, эрэмбэ, хуудаслалт, бүртгэлийн үйлдлүүд |

Жагсаалт нь бүх нийтлэлийн төлөв, зарагдсан бүртгэлийг харуулах боломжтой. Хайлт нь гарчиг, картын гарчиг, марк, загвар, хувилбарт үйлчилнэ. Лавлах, enum, үнэ/он/гүйлтийн хязгаар болон онцлох шүүлтийг Vehicles.listQuery contract-аас хэрэглэнэ. Хайлт/шүүлт/эрэмбэ/limit/offset URL query-д хадгалагдана; form-оос буцахад жагсаалтын нөхцөл хэвээр байна. Мөр бүр засах болон боломжтой төлөвийн үйлдлийн menu-тай; hard delete байхгүй.

## Форм

- Mantine `useForm`, DTI schema validation, цагаан PageBody, хамгийн ихдээ 850px өргөн. Desktop хоёр, mobile нэг баганатай талбарууд.
- Доорх 7 tab-аар талбаруудыг бүлэглэнэ. Нэг талбар нэг tab-д байна; Хадгалах нь бүх tab-ийн өөрчлөлтийг хамтад нь хадгална. Алдаа гарвал эхний алдаатай талбарын tab руу шилжинэ. Mobile дээр tab мөр хөндлөн гүйлгэгдэж, идэвхтэй tab харагдах хэсэгт орно.
- Ноорогт гарчиг заавал; бусад талбарыг дутуу хадгалж болно. Нийтэлсэн бүртгэлийг засахад нийтлэх шаардлагыг хангана. Нийтлэх action-ийн эцсийн шалгалтыг backend хийнэ.
- Марк солиход загвар/хувилбар, загвар солиход хувилбар цэвэрлэгдэнэ. Цахилгаан түлш сонгоход engineCapacityCc цэвэрлэгдэнэ.
- Үйлдвэрлэсэн он, орж ирсэн он нь таслал болон stepper-гүй text input байна. Хадгалах үед дөрвөн оронтой оныг number болгож, оны хязгаар болон хоорондын дарааллын дүрмийг хэвээр шалгана; хоосон утга null байна.
- Өмнө хадгалсан идэвхгүй лавлахыг хэвээр үлдээж болно; шинээр сонгох лавлах болон түүний ancestor идэвхтэй байна.
- Edit нь зөвхөн өөрчлөгдсөн талбаруудыг PATCH хийнэ. Талбар цэвэрлэхэд null, gallery/тоноглолыг цэвэрлэхэд хоосон array илгээнэ.
- Хадгалалт амжилттай бол идэвхтэй tab дээрээ үлдэнэ. Шинэ бүртгэлийг анх хадгалж edit хуудас руу шилжихэд мөн сонгосон tab-ийг хадгална; validation алдаа гарвал алдаатай талбарын tab руу шилжих дүрэм хэвээр.
- Хадгалж/upload хийж байх үед давхар үйлдлийг хориглоно. Алдахад утгаа хадгална; хадгалаагүй өөрчлөлттэй үед гарахыг баталгаажуулна.
- Нийтлэх, нуух, архивлах, сэргээх нь тусдаа confirmation-тай. Формын өөрчлөлтийг эхлээд хадгалж байж төлөвийн menu идэвхжинэ. Архиваас сэргээхэд hidden болно.

## Зураг ба агуулга

- Үндсэн болон картын зураг дээр шууд нэг файл upload хийхэд тухайн талбарт автоматаар сонгоно. Шинээр upload хийсэн файл галерейд мөн нэмэгдэнэ. Галерей дээр олон файл upload хийх боломж хэвээр.

- Олон файл сонгож, тус бүр title/description оруулан нэг нэг multipart хүсэлтээр upload хийнэ. Амжилттай болсон файлуудыг хадгалж, алдаатай upload-ыг дахин оролдож болно.
- Формат, browser дүрслэх чадвар, нийт зургийн тоо шалгахгүй. Нэг файлын хэмжээг backend ConfigFiles тогтооно; frontend тусдаа тогтмол хязгаар давхардуулахгүй.
- Үндсэн болон картын зургийг энэ бүртгэлтэй холбоотой/шинээр upload хийсэн файлуудаас сонгоно. Галерейн дарааллыг дээш/доош өөрчилж, холбоос хасаж, тухайн формд байгаа файлыг дахин нэмнэ. Файл өөрөө устахгүй.
- Галерейгаас хасах нь mainImageId/itemImageId сонголтыг автоматаар цэвэрлэхгүй. Usage-г frontend засахгүй; хадгалахад backend transaction шинэчилнэ.
- Upload хийсний дараа формоос хадгалахгүй гарвал ашиглагдаагүй файл үлдэж болно; автомат устгал хийхгүй.
- Item талбарууд сонголттой; хоосныг render дээр үндсэн талбаруудаас нөхөх дүрэм хэвээр. UI нь эдгээрийг хадгалах үед хуулбарлаж бөглөхгүй.
- `content` нь Mantine Tiptap rich text editor-оор засах HTML. Heading, bold/italic/underline, жагсаалт, холбоос, undo/redo дэмжинэ. Өөрчлөгдөөгүй HTML-ийг PATCH-д оруулахгүй. Зассан HTML нь editor-ийн дэмжих бүтэц рүү хэвийнждэг.

## Хүрээнд ороогүй

Бүх файлын нэгдсэн browser, өмнөх файлын metadata засах/delete API, сэлбэг/дугуйн product form, website дэлгэц, CRM болон Userly/ACL integration нэмээгүй. Rich text-ийн HTML sanitization/public render хамгаалалтыг editor өөрөө бүрэн орлохгүй; production агуулгын бодлогыг тусад нь шийднэ.
