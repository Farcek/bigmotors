# Бүтээгдэхүүний нийтлэг дүрэм

- Огноо: 2026-09-10
- Төлөв: Баталсан
- Үндэслэл: Хэрэглэгч сэлбэг, дугуйд автомашинтай ижил зарчим, дүрмүүдийг хэрэглэхээр баталсан
- Холбоотой баримт: [Автомашин](vehicle-fields.md), [Сэлбэг](part-fields.md), [Дугуй](tire-fields.md), [Лавлахын тойм](../db/README.md)

## Хүрээ

Автомашинд баталсан, бүтээгдэхүүний төрлөөс үл хамаарах дүрмүүдийг гурван төрөлд ижил хэрэглэнэ. Нийтлэг дүрмийн цаашдын өөрчлөлтийг энд хөтөлнө; төрөл тус бүрийн баримт онцлог талбар болон нэмэлт шаардлагыг хариуцна. Энэ нь сэлбэгийн 25, дугуйн 33 талбарын үлдсэн онцлог саналыг бүхэлд нь баталсан эсвэл DB schema үүсгэсэн гэсэн үг биш.

## Нийтлэг талбарын зураглал

| Мэдээлэл | Автомашин | Сэлбэг | Дугуй | Ижил дүрэм |
| --- | --- | --- | --- | --- |
| Үндсэн гарчиг | V01 | P01 | T01 | Ноорог/нийтлэхэд заавал; 255 тэмдэгт хүртэл |
| Үнэ | V21 | P13 | T21 | Доорх үнэ/валютын дүрэм |
| Валют | V22 | P14 | T22 | Зөвхөн `MNT` |
| Үнэ харуулах хэлбэр | V23 | P15 | T23 | `show_price`, `inquire`; нийтлэхэд заавал, автоматаар сонгохгүй |
| Үндсэн зураг | V27 | P20 | T28 | Ноорогт сонголттой, нийтлэхэд upload дууссан зураг заавал |
| Нэмэлт зургууд, дараалал | V28 | P21 | T29 | Сонголттой; тоонд дээд хязгааргүй, дараалалтай |
| Товч тайлбар `description` | Нийтлэг нэмэлт | Нийтлэг нэмэлт | Нийтлэг нэмэлт | Short description, SEO, share-д ашиглана; 512 тэмдэгт хүртэл; ноорог/нийтлэхэд сонголттой |
| Үндсэн агуулга `content` | V30 | P22 | T30 | Дэлгэрэнгүй танилцуулгын үндсэн rich text агуулга; сонголттой; 512 тэмдэгтийн хязгаар хамаарахгүй |
| Нийтлэлийн төлөв | V31 | P23 | T31 | Анх `draft`; доорх ижил шилжилт |

## Текст ба item талбарууд

- Бүх гарчиг/`title`, түүний дотор `item_title` болон зураг бүрийн гарчиг хамгийн ихдээ 255 тэмдэгт.
- `description` нь энгийн текст товч тайлбар бөгөөд short description, SEO, share зэрэгт ашиглана. 2026-09-10-нд ноорог болон нийтлэхэд заавал биш гэж баталсан; хоосон байгаагаас нийтлэхийг зогсоохгүй. `description`, `item_desc` болон зураг бүрийн тайлбар хамгийн ихдээ 512 тэмдэгт.
- `content` нь дэлгэрэнгүй танилцуулгын хуудасны үндсэн rich text агуулга. 2026-09-10-нд HTML хэлбэрээр DB-ийн `text` баганад хадгалахаар баталсан; сонголттой/nullable. `description`-оос тусдаа; 512 тэмдэгтийн хязгаар хамаарахгүй.
- `item_title`, `item_desc`, `item_image_id` нь ноорог болон нийтлэхэд бүгд сонголттой. Өмнөх баримтын `item_image` нь жагсаалтын зургийн ойлголт; schema-д `item_image_id` нэрээр тэмдэглэнэ.
- Render үед бөглөөгүй `item_title`-ийг `title`, `item_desc`-ийг `description`, `item_image_id`-ийг `main_image_id`-аас тус тус автоматаар авна. Бөглөсөн item утга давуу эрхтэй; талбар бүрийн fallback бие даасан байна.
- Fallback нь зөвхөн харуулах үеийн үйлдэл; үндсэн утгыг item талбарт хуулж хадгалахгүй. Үндсэн утга өөрчлөгдвөл хоосон item талбарын render мөн шинэчлэгдэнэ. `item_desc` болон `description` хоёул хоосон бол тайлбар харуулахгүй; `content`-оос автоматаар тайлбар үүсгэхгүй.
- Утгатай текст шаардсан талбарт зөвхөн зай бичсэнийг бөглөсөнд тооцохгүй. Хэт урт текстийг тасалж хадгалахгүй; ноорогт ч уртын шалгалт үйлчилнэ.
- Title/desc-ийн хязгаар нь SKU, part number, OEM дугаар, индекс болон бусад бүх text талбарт автоматаар хамаарахгүй. Тэдгээрийг арлын дугаартай адил давхардал зөвшөөрсөн гэж үзэхгүй.
- Хадгалах формат HTML `text` гэж тогтсон. Rich text editor-ийн сан, toolbar, HTML sanitization/аюулгүй харуулах механизм болон тусдаа уртын хязгаар нээлттэй; media embed автоматаар батлагдахгүй.

## Зураг

- Эх файлыг серверийн hard disk дээр, зургийн зам болон metadata-г `product_images` хүснэгтэд хадгална. [Хадгалалтын шийдвэр ба DB санал](../db/product-images.md); upload implementation хараахан хийгдээгүй.
- Зургийн тоонд дээд хязгааргүй. Нэмэлт зураг болон `item_image_id` сонголттой; үндсэн зураг `main_image_id` нийтлэхэд заавал хэвээр.
- Зураг бүр сонголттой гарчиг, тайлбартай; дээрх 255/512 уртыг хэрэглэнэ.
- Форматыг тогтсон жагсаалтаар хязгаарлахгүй; upload хийсэн эх зургийг өөрчлөлтгүй хадгалж ашиглана.
- Браузер харуулж чадах эсэхийг шалгахгүй. Харуулж чадахгүй байсан ч upload/хадгалах/нийтлэхийг хориглохгүй; тусгай preview, хөрвүүлэлт, орлуулах зураг шаардахгүй.
- Upload дууссан зураг сонгох шаардлага хэвээр. Зургийн форматын хязгааргүй байдал нь зураг биш дурын файл болон аюултай upload/serve-ийг зөвшөөрсөн гэсэн үг биш.
- Файл/пикселийн техникийн хязгаар, metadata-ийн public харагдах байдал, устгах/хадгалах хугацаа нээлттэй.

## Үнэ ба валют

- Үнэ `MNT` нэгжтэй бүхэл тоо, `1–99,999,999,999` хязгаарт байна. Бутархайг автоматаар бүхэл болгохгүй; хоосон утгыг `0` болгохгүй.
- `show_price` үед нийтлэхэд үнэ, валют заавал. `inquire` үед үнэ сонголттой; үнэ оруулсан бол нийтлэхэд валют мөн заавал.
- Ноорогт үнэ хоосон байж болно; бөглөсөн үнэ дээр тоон хязгаарын шалгалт үйлчилнэ.
- `inquire` үед дотоод үнэ байсан ч нийтэд үнийн дүн харуулахгүй. Бусад үед бүтэн дүнг бүлэглэж харуулна, жишээ нь `84,500,000 ₮`.
- Сэлбэг, дугуйн үнэ заасан нэгжид хамаарна. Ширхэг/хос/иж бүрдлийн сонголт болон нэгжийн нэмэлт шаардлага тусдаа; энэ дүрэм агуулахын үлдэгдэл хөтлөхийг батлахгүй.

Валют, үнэ харуулах хэлбэр, нийтлэлийн төлөвийн ижил утгуудыг `packages/core`-д дундын enum/const байдлаар хөтөлнө. TypeScript identifier болон DB хадгалалтын төрөл хараахан тогтоогүй.

## Ноорог, нийтлэх ба төлөв

- Ноорог үүсгэхэд хэрэглэгчээс зөвхөн үндсэн гарчгийг шаардана; нийтлэлийн төлөв `draft`, онцлох эсэх `false` байна. Бусад тодорхойгүй утгыг тааж бөглөхгүй.
- Нийтлэхэд дээрх нийтлэг болон тухайн төрлийн батлагдсан нэмэлт шаардлагыг шалгана. Нийтлэгдсэн мэдээллийг засаж хадгалахад мөн шалгана; заавал мэдээллийг хасах бол эхлээд нийтэд харагдахгүй төлөвт шилжүүлнэ.
- Сэлбэг, дугуйн төрөлд тусгайлан шаардах талбарын бүрэн matrix нээлттэй; зөвхөн нийтлэг шаардлага хангаснаар бүх нийтлэх шалгалт бүрэн тогтсон гэж үзэхгүй.
- Хоосон, тодорхойгүй утга нь `0`, `false`, "бүх төрөлд тохирно" гэсэн утгатай биш. Онцлох эсэхийн зориуд баталсан default-оос бусад boolean-ийг тааж тохируулахгүй.

| Нийтлэлийн шилжилт | Дүрэм |
| --- | --- |
| `draft -> published` | Нийтлэх шаардлагыг шалгана |
| `published -> hidden` | Сайтаас түр нууна |
| `hidden -> published` | Нийтлэх шаардлагыг дахин шалгана |
| `draft / hidden / published -> archived` | Нийтээс гаргаж, бүртгэлийг хадгална |
| `archived -> hidden` | Сэргээхэд шууд нийтлэхгүй |

Зөвхөн `published` бүтээгдэхүүн нийтэд харагдана; бусад төлөвийн мэдээлэл шууд холбоосоор ч нээлттэй биш. Нийтлэлийн төлөвийг бэлэн байдалтай нэгтгэхгүй, бэлэн байдал өөрчлөгдөхөд нийтлэлийн төлөвийг автоматаар солихгүй.

Автомашины `available/sold`, ирэлтийн төлөв болон `sold`-ийг жагсаалтаас хасах дүрмийг сэлбэг/дугуйд шууд хуулбарлахгүй. Эдгээр нь олон ширхэгийг төлөөлдөг тул нэгийг борлуулснаар бүх бүтээгдэхүүн зарагдсан болохгүй. Түр дууссан/ирэх бүтээгдэхүүнийг жагсаалтад харуулах болон бэлэн байдлын бүрэн утга, шилжилт тусдаа шийдэгдэнэ.

## Лавлахын удирдлага

- Admin лавлах нэмэх, нэр засах, идэвхгүй болгох боломжтой; ашиглагдаж байгаа лавлахыг шууд устгахгүй.
- Шинэ бүртгэл болон өөрчилж буй сонголтод зөвхөн идэвхтэй лавлах сонгоно.
- Өмнө сонгосон лавлах идэвхгүй болсон бол холбоосыг хадгална. Бусад мэдээллийг засах, шаардлага хангасан ноорог/нуусан бүтээгдэхүүнийг нийтлэхэд заавал солихыг шаардахгүй.
- Public талд өмнөх лавлахын нэр хэвийн харагдана; "идэвхгүй" тэмдэглэгээ зөвхөн admin-д байна. Лавлах идэвхгүй болсноор бүтээгдэхүүнийг автоматаар нуухгүй.
- Эцэг сонголт солигдоход тохирохгүй доод сонголтуудыг цэвэрлэнэ. Сэлбэгийн үндсэн/дэд ангилал, нийцлийн марк/загвар, дугуйн брэнд/загварт энэ зарчим ижил үйлчилнэ. Сонголттой талбарыг заавал болгохгүй; төрөл тус бүрийн хамаарлын шалгалт хэвээр.
- Enum/const утгыг admin-аас дурын лавлах шиг нэмэхгүй. Өөр өөр төрлийн үйлдвэрлэгч, загварын лавлахыг зөвхөн ижил дүрэмтэй гэдгээр нэгтгэхгүй.

## Public каталог ба ACL

- Карт дээр item талбаруудыг дээрх render fallback-тай харуулна; тайлбар нь fallback-ийн дараа утгатай үед харагдана. Үнэ/үнэ асуух мэдээлэлтэй; дарахад дэлгэрэнгүй нээнэ. Бусад сонголттой үзүүлэлт хоосон бол зохиомол утга харуулахгүй; responsive багана автомат байна.
- Өөр талбарын шүүлтүүд `AND`; идэвхтэй шүүлтийн талбар хоосон бүтээгдэхүүн таарахгүй. Сонгосон шүүлт, үр дүнгийн тоо, тус бүрийг болон бүгдийг цэвэрлэх үйлдэл ижил байна.
- Үнийн хүрээнд "Үнэ асуух" бүтээгдэхүүнийг оруулахгүй. Үнэ өсөх/буурах эрэмбийн хоёр чиглэлд "Үнэ асуух" бүтээгдэхүүн сүүлд байна.
- Анхны эрэмбэ анх нийтэлсэн огноогоор буурах; засвар хийснээр дээшлэхгүй. Сэлбэг/дугуйн нэмэлт үзүүлэлт, текст хайлтын талбар, тусгай шүүлт/эрэмбийг дараа тогтооно; автомашины гүйлт/оны шүүлтийг шууд хуулбарлахгүй.
- Дотоод тэмдэглэл нийтэд харагдахгүй. Нийтлэлийн төлөв, онцлох эсэхийг бүтээгдэхүүний техникийн үзүүлэлтийн мөр болгохгүй.
- [Userly admin ACL](admin-authentication-access.md) бүх төрөлд үйлчилнэ; permission нь нийтлэх validation болон төлөв шилжилтийн шаардлагыг алгасахгүй. Public каталогт admin login шаардахгүй.

## Хүлээн авах шалгуур

1. Сэлбэг/дугуйг зөвхөн гарчигтай ноорог хадгалахад `draft`, онцлох `false` болно. Бөглөсөн текст/үнийн хязгаарыг шалгана.
2. Үндсэн зураг дутуу бол нийтлэхийг зогсооно. `item_*` хоосон байгаагаас нийтлэхийг зогсоохгүй; render үед `title`, `description`, `main_image_id`-аас тус тус орлуулна. Item утга бөглөсөн үед үндсэн утгыг давна; fallback утгыг DB-д хуулж хадгалахгүй.
3. Гарчиг 255, `description` болон бусад товч тайлбар 512 тэмдэгт байж болно; хэтэрвэл хадгалахгүй. Rich text `content`-д 512-ын хязгаар хэрэглэхгүй; `item_desc`-ийн fallback болгон ашиглахгүй.
4. Зургийн тоо болон браузерын форматын дэмжлэгээс болж upload/нийтлэхийг хориглохгүй; эх файл хэвээр хадгалагдана.
5. Өмнөх идэвхгүй лавлахтай бүтээгдэхүүнийг бусад шаардлага хангавал засаж, нийтэлж болно; шинээр идэвхгүй утга сонгохгүй, эцэг/хүүхдийн хамаарлыг шалгана.
6. Нуусан/архивласан/ноорог бүтээгдэхүүн шууд холбоосоор нийтэд харагдахгүй; архив сэргээхэд `hidden` байна.
7. `inquire` үнийг нийтэд задруулахгүй, үнийн хүрээнд оруулахгүй, үнийн эрэмбэд сүүлд байрлуулна.
8. Сэлбэг/дугуйн нэг ширхэг борлогдсоноор бүх бүтээгдэхүүнд автомашины `sold` төлөв оноохгүй.

## Үлдсэн зааг

Сэлбэгийн нийцэл, part number/OEM/SKU, үнийн нэгж/савлагаа; дугуйн хэмжээ/индекс/хийц/улирал, ширхэг/иж бүрдлийн ялгаа; төрөл тус бүрийн нөхцөл ба бэлэн байдлын enum; нэмэлт requiredness/public/filter matrix нь тухайн төрлийн баримтад нээлттэй хэвээр. Код, DB schema, migration болон tech spec task-ийн төлөв өөрчлөгдөөгүй.
